# Andriloft 0.3.1

## Changes

- Correct stale v0.1 descriptions in the app and current documentation. The compatibility screen reads the app's bundle version, matching the sidebar and About window, and describes the supported API subset without a fixed release number.
- Update local development bundle defaults to `0.3.1 (9)`, the planned patch following the published `v0.3.0` release. Release builds continue to receive their version and increasing build number from the SemVer planner.
- Add mandatory contributor guidance and a pull request checklist for all maintained version references, release notes, compatibility descriptions, and validation information outside the bot's generated output. Future updates must reflect their Conventional Commit type and actual changes.

## Current functionality and limits

This patch retains the APKMirror marketplace and Google Antigravity cloud APK selection introduced in 0.3.0, signed in-app updates, and the existing Android runtime. It adds no Android API support. The bundled example can run basic Java activities, native controls, click callbacks, text input, and saved preferences. Downloading another APK does not establish that it can run.

AndroidX, Compose, XML layout inflation, Google Play services, WebView, Android network/media/device services, and JNI/Linux native libraries remain unsupported. See the [README](../../README.md#current-limits), [marketplace guide](../MARKETPLACE.md), and [validation record](../../VALIDATION.md) for the implemented features and observed checks.

## Download and install

The [latest published GitHub release](https://github.com/culpen90/Andriloft/releases/latest) is the authority for publication status and available downloads. Each release provides a universal macOS DMG and ZIP, a signed update feed, checksums, and source metadata. macOS 13 or newer is required; signing is ad hoc without Apple notarization. Follow the [installation guide](../INSTALL.md) for first launch and in-app updates.
